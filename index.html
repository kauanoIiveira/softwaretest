01. Conceito

O que é teste de software?

Teste de software é a execução planejada de um sistema para comparar o resultado obtido com o resultado esperado. Quem testa cria cenários, usa dados definidos e registra o que aconteceu.

Ao testar, a equipe verifica os requisitos e encontra defeitos antes da publicação. Ela usa o resultado como evidência do comportamento observado, não como prova de que o sistema está livre de erros.

Diferenciando os termos

Erro

Uma pessoa interpreta ou implementa uma regra de forma incorreta.

Defeito / Bug

O erro deixa um problema no código, na interface ou na regra de negócio.

Falha

Durante o uso, o sistema produz um resultado diferente do esperado.

02. Por que testar

Por que testar?

A equipe corrige um defeito com menos custo quando ainda trabalha na mesma alteração. Depois da publicação, o mesmo problema pode interromper o serviço, expor dados e exigir uma correção urgente.

Com testes, a equipe:

  • Encontra defeitos antes da publicação.
  • Confirma regras de negócio com cenários verificáveis.
  • Detecta quando uma alteração quebra uma função pronta.
  • Mede o comportamento do sistema sob carga.
  • Revela acessos indevidos e exposição de dados.
  • Reduz o retrabalho depois da entrega.
  • Registra evidências para aprovar ou rejeitar uma versão.
03. Casos reais

Projetos afetados por falhas de software

Estes projetos acumularam defeitos, atrasos ou problemas de integração e não chegaram à operação planejada.

ABANDONADO

FBI Virtual Case File

O FBI encomendou o Virtual Case File para organizar investigações. A equipe de revisão registrou quase 400 problemas. A agência considerou o sistema inadequado para uso e encerrou o projeto.

Fonte: FBI Archives
PARALISADO

Canadian Firearms Information System II

O governo canadense contratou um novo sistema para substituir o cadastro de armas. No prazo previsto, o governo ainda não tinha uma aplicação funcional e os testes indicavam problemas de desempenho. O governo suspendeu o trabalho.

Fonte: House of Commons Canada
ENCERRADO

FiReControl, Reino Unido

O governo britânico planejou uma rede nacional para substituir as salas locais de controle dos bombeiros. Em 2010, encerrou o projeto sem colocar em operação o sistema previsto.

Fonte: UK Parliament
ATRASADO

Sistema de bagagens do Aeroporto de Denver

Durante os testes do sistema automatizado de bagagens, a equipe encontrou problemas graves. As correções atrasaram a abertura do aeroporto, e a solução completa não entrou em operação como planejado.

Fonte: Computerworld
04. Categorias

Tipos de teste de software

UNIT

Teste unitário

Executa uma função ou método de forma isolada.

INTG

Teste de integração

Confere a troca de dados entre módulos, serviços ou bancos.

SYS

Teste de sistema

Executa o sistema completo no ambiente de teste.

UAT

Teste de aceitação

O cliente ou usuário confirma se a entrega atende ao combinado.

FUNC

Teste funcional

Compara a resposta de cada função com o requisito.

REGR

Teste de regressão

Repete testes já aprovados depois de uma alteração.

PERF

Teste de desempenho

Mede tempo de resposta, estabilidade e uso de recursos.

LOAD

Teste de carga

Simula muitos acessos ou operações ao mesmo tempo.

SEC

Teste de segurança

Procura acessos indevidos, vazamentos e configurações frágeis.

UX

Teste de usabilidade

Observa se o usuário entende a interface e conclui tarefas.

MAN

Teste manual

Uma pessoa executa o cenário e registra o resultado.

AUTO

Teste automatizado

Um script executa verificações repetíveis e compara resultados.
